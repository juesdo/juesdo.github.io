0x01 前言

1. 什么是序列化与反序列化？

  • 序列化 (Serialization)： 把内存中的 Java 对象转换成“字节序列”（一串 0 和 1）的过程。这就像是把你组装好的立体积木城堡拆解、编号，并整齐地装进盒子里。
  • 反序列化 (Deserialization)： 把字节序列重新恢复成 Java 对象的过程。这就像是打开盒子，照着编号把积木重新拼回那个立体的城堡。

2. 为什么需要它？

  • 持久化保存（存档）： 内存断电即焚。如果你想把游戏里玩家的当前属性（生命值、装备等对象）保存到硬盘上，就需要序列化。
  • 网络传输： 网络电缆里只能跑 0 和 1 的字节流，不能直接塞进去一个立体的 Java 对象。所以得先“压扁”（序列化）发送，接收端再“充气”（反序列化）还原。

3. Java 实现的三大关键点

要在 Java 中使用这项技术，你需要记住三个核心要素：

  • Serializable 接口： 想要被序列化的类，必须实现 java.io.Serializable 接口。这是一个神奇的“标记接口”，里面什么方法都没有，纯粹是为了给 Java 虚拟机盖个章，表示“我允许被打包”。
  • transient 关键字： 如果对象里有些敏感信息（比如 password）你不想存入硬盘或发到网上，就在这个变量前加 transient，序列化时就会自动跳过它。

  • ObjectOutputStream 和 ObjectInputStream： 这两个流专门用来负责对象的写出和读入。

FileOutputStream（基础水管 / 节点流）： 唯一的本领就是跟硬盘上或网络的文件建立物理连接。但它很笨，只认识最基础的字节（0和1），根本不知道什么是 Java 对象。

ObjectOutputStream（加工滤芯 / 处理流）： 能把复杂的 Java 对象拆解（序列化）成一长串字节。但是，它没有能力直接去连接硬盘或者网络。

这里的自定义readObject()不能理解为“重写”， 如果在该方法上加上 @Override 注解，编译器会直接报错。 因为Java序列化规范规定该方法必须是private方法，而private 方法属于类的私有实现，既不能被子类继承，也不能被子类重写。 因此它的底层的运行机制其实是通过反射调用：

  • 当调用 ois.readObject() 时，底层反序列化引擎会通过反射（Reflection）检查当前正在恢复的类中是否存在上述签名的私有方法。
  • 如果声明了：JVM 会绕过常规访问限制，通过反射直接调用类里写好的 readObject。
  • 如果没有声明：JVM 会退回使用默认策略（按字节顺序为字段逐一赋值）。
